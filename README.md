# Спулирование трубопроводов: изометрии PDF → заявка в Excel

Программа читает новые изометрии из PDF, разбивает каждую линию на спулы и
собирает заявку на материалы в том же виде, в каком она заполняется вручную —
по образцу листа «Евгений (2)».

Эталонная заявка для работы не нужна: программа читает сами чертежи. Из
рабочей книги берётся только справочник «База» (Ident → перевод, наименование,
единица измерения), и выгрузить его достаточно один раз.

## Запуск

### Окно программы

1. Установить [Python](https://www.python.org/downloads/), при установке
   отметить галочку **«Add python.exe to PATH»**.
2. Скачать эту папку и распаковать куда угодно.
3. Запустить **`run.bat`** двойным щелчком — откроется окно.

В окне три шага:

* **Чертежи** — «Выбрать файлы PDF…» или «Выбрать папку…»;
* **Справочник «База»** — один раз указать рабочую книгу `.xlsx`, дальше
  справочник берётся сам;
* **Собрать заявку** — программа спросит, куда сохранить, и покажет ход
  работы. По готовности — кнопки «Открыть заявку» и «Показать в папке».

Библиотеки ставятся сами при первом запуске.

### Без окна

Файлы, перетащенные на значок `run.bat`, обрабатываются сразу, без окна:
PDF считаются чертежами, `.xlsx` — рабочей книгой со справочником.

```bash
pip install -r requirements.txt

# первый раз — забрать справочник «База» из рабочей книги
python -m spooler новые_изометрии.pdf --book "рабочая книга.xlsx"

# дальше книга не нужна
python -m spooler новые_изометрии.pdf -o Заявка.xlsx

# можно скормить сразу папку
python -m spooler C:\изометрии\1401
```

На выходе книга с двумя листами:

* **Заявка** — колонки A–Q как в образце, шапка помечает «Автоматически» /
  «Вручную», одна строка = один материал в одном спуле;
* **Расхождения** — всё, где программе нельзя доверять на слово: цеховые швы,
  которых нет в ведомости, непрочитанные таблицы, Ident, которого нет в
  «Базе», несовпадение числа спулов с разметкой на чертеже.

Если позиции нет в «Базе», строка всё равно заполняется: тип детали
определяется по английскому описанию из спецификации (Pipe → Труба,
Elbow → Отвод, Olet → Бобышка и так далее), а сама позиция попадает в
«Расхождения» — чтобы вы добавили её в справочник.

## Как это работает

**OCR не нужен.** На листах nanoCAD-экспорта текст выведен кривыми, и
`get_text()` возвращает пустоту. Но каждая надпись сохранена как PDF-аннотация
типа `Square`: в `/Contents` лежит сам текст, в прямоугольнике — координаты.
Так читаются штамп, спецификация и ведомость швов — точно, без распознавания.

Дальше — разбивка на спулы:

| Что | Правило |
|---|---|
| **SP** | детали, связанные между собой цеховыми (S) швами |
| **E-SP** | деталь спецификации FABRICATION без цеховых швов и без выхода за лист — «спул без сварки» по легенде чертежа |
| граница спула | монтажный (F) шов |
| не входит в спул | всё из спецификации ERECTION |
| нумерация | сквозная по линии, по ходу трубы; если на чертеже размечено столько же спулов, сколько насчитала программа, нумерация берётся с чертежа |

Два случая, которые ведомость швов прямо не показывает, но без них разбивка
разъезжается:

* **Ссылка на соседний лист.** Нумерация деталей у Intergraph своя на каждом
  листе, поэтому шов на стыке листов ссылается на номер с продолжения — и
  выглядит как лишний стык у трубы. Отличается перебором концов: у трубы и
  отвода их два, у тройника три, приварка бобышки (LET) конец не занимает.
  Всё сверх нормы — ссылка за лист, склеивать по ней нельзя.
* **Спул, уходящий за лист.** Если у детали остался свободный конец, её
  цеховой шов находится на соседнем листе. Такой спул сварной (SP, не E-SP),
  а нумерация на следующем листе продолжается с того же номера.

Количество суммируется по паре (спул, Ident): труба — в миллиметрах,
фасонные изделия — в штуках. Перевод, наименование и единица измерения
берутся из справочника по `Ident`, DN — из колонки SIZE спецификации,
дюймы — по таблице пересчёта из «Базы».

## Насколько можно доверять

Логика проверена на уже заполненной заявке: 12 изометрий проекта
NKNH21002-1401, 60 спулов.

| | |
|---|---|
| Совпало полностью — состав деталей, количества и номер спула | **56 (93 %)** |
| Верный состав, номер спула отличается | 3 |
| **Верный состав всего** | **59 из 60 (98 %)** |
| Изометрий сошлись целиком | 9 из 12 |

«Верный состав» — совпадение по деталям и количеству до миллиметра.

Эта сверка — регрессионный тест, а не часть работы программы:

```bash
python tests/check_etalon.py изометрии.pdf etalon.json
```

## Что программа не берёт на себя

Цеховые швы, нанесённые на чертёж поверх `WELDING LIST` (`S22`, `S30`–`S49` и
подобные). В таблице их нет, а на чертеже они — подписи с координатами: чтобы
понять, какую именно трубу такой шов режет, нужен разбор геометрии линий
чертежа, а не текста. Такие листы помечаются в «Расхождениях» с перечнем
швов — видно, что проверять руками.

## Форматы изометрий

Разбираются оба формата, которые встречаются в подшивке.

**Intergraph / nanoCAD.** Текст выведен кривыми, но сохранён в PDF-аннотациях.
Есть `WELDING LIST` — спулы считаются по нему, как описано выше.

**Российский, из AutoCAD (СИБУР).** Текст обычный, шрифтовой, а ведомости швов
нет вообще. Зато на чертёж уже нанесена разметка спулирования, и разбивка
читается прямо с неё:

* подписи спулов (`SP01`, `SP02.1` — уточнение того же спула) стоят у своих
  участков. На одних листах это обычный текст, на других — аннотации
  AutoCAD SHX Text, читаются оба варианта;
* длина отрезка трубы подписана вплотную к своему размеру и всегда меньше
  его, потому что из размера вычтены отводы: у «2094» рядом стоит «1910».
  Где длины набраны мельче размеров, хватает кегля; где кегль одинаковый,
  в связке берётся наименьшее число;
* номера позиций спецификации вынесены на полки выносок — повёрнутых как
  придётся, поэтому опознаются по значению: это номер строки спецификации,
  а не размер и не диаметр.

Каждая подпись относится к ближайшему спулу — так и собирается состав. Какая
именно это труба, подсказывает ближайшая выноска: на одной линии их бывает
несколько, разного материала. Позиции ниже DN50 в заявку не идут, а бобышка
на основной трубе идёт: у неё основной диаметр трубный. Образцы из «Условных
обозначений» отбрасываются — иначе всё ближайшее уехало бы в несуществующий
спул.

Итоги сверяются со спецификацией листа: если сумма длин по чертежу не сходится
с `Qty`, или позиция спецификации на чертеже не найдена, это попадает в
«Расхождения» отдельной строкой. На проверенной изометрии
`270110371MN` программа собрала 7 строк из 9 — не хватило двух фланцев, у
которых на чертеже нет выноски с номером позиции; про них она честно написала.

## Структура

```
spooler/
  pdf_reader.py    чтение аннотаций: штамп, MATERIAL LIST, WELDING LIST, разметка
  spools.py        граф деталей, разбивка на SP/E-SP, нумерация по ходу трубы
  sibur.py         второй формат изометрий (AutoCAD, разметка прямо на чертеже)
  models.py        общие типы
  reference.py     справочник «База», таблица DN ↔ дюймы, перевод по описанию
  excel_writer.py  выгрузка в формате образца + лист расхождений
  gui.py           окно программы (tkinter, входит в состав Python)
  job.py           общий ход работы для окна и командной строки
  cli.py           командная строка
run.bat            запуск под Windows
```
