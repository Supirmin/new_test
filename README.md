# Спулирование трубопроводов: изометрии PDF → заявка в Excel

Программа читает изометрии из PDF, разбивает каждую линию на спулы и собирает
заявку на материалы в том же формате, который сейчас заполняется вручную
(эталон — лист «Евгений (2)» рабочей книги).

## Как это работает

**OCR не нужен.** На листах nanoCAD-экспорта текст выведен кривыми, и
`get_text()` возвращает пустоту. Но каждая надпись сохранена как PDF-аннотация
типа `Square`: в `/Contents` лежит сам текст, в прямоугольнике — координаты.
Так читаются штамп, спецификация и ведомость швов — точно, без распознавания.

Дальше — разбивка на спулы:

| Что | Правило |
|---|---|
| **SP** | детали, связанные между собой цеховыми (S) швами |
| **E-SP** | деталь спецификации FABRICATION, которой не касается ни один цеховой шов — «спул без сварки» по легенде чертежа |
| граница спула | монтажный (F) шов |
| не входит в спул | всё из спецификации ERECTION |
| нумерация | сквозная по линии, по ходу трубы: спулы сцеплены монтажными швами в цепочку, обход с детали с наименьшим номером |

Количество суммируется по паре (спул, Ident): труба — в миллиметрах,
фасонные изделия — в штуках. Перевод, наименование и единица измерения
берутся из справочника «База» рабочей книги по `Ident`.

## Проверка на реальных данных

Сверка с эталонным листом «Евгений (2)» по 11 изометриям проекта NKNH21002-1401:

* **51 из 58** выданных спулов совпал с эталоном один в один — по составу
  деталей и по количеству, до миллиметра;
* 5 изометрий совпали полностью, включая нумерацию SP/E-SP.

Где расходится — там в чертёж вручную добавлены цеховые швы, которых нет в
`WELDING LIST` (дополнительная резка под транспорт). Программа их не
придумывает: такие листы попадают в лист «Расхождения» с перечнем швов.

## Запуск

```bash
pip install -r requirements.txt
python -m spooler.cli изометрии.pdf --book "рабочая книга.xlsx" -o Заявка.xlsx
```

`--book` нужен только ради листа «База» — справочник не дублируется в
репозиторий, а читается из рабочей книги.

На выходе книга с двумя листами:

* **Заявка** — колонки A–Q как в эталоне, шапка помечает «Автоматически» /
  «Вручную»;
* **Расхождения** — всё, где программе нельзя доверять на слово: швы вне
  ведомости, стыки, уходящие за пределы листа (`6-*`), непрочитанные таблицы,
  Ident, которого нет в «Базе», несовпадение числа спулов с разметкой на чертеже.

## Сверка с эталоном

```bash
python tests/check_etalon.py изометрии.pdf etalon.json
```

`etalon.json` — выгрузка ожидаемого состава спулов из листа «Евгений (2)»
в виде `{изометрия: {спул: {Ident: [перевод, единица, количество]}}}`.

## Структура

```
spooler/
  pdf_reader.py    чтение аннотаций: штамп, MATERIAL LIST, WELDING LIST, разметка
  spools.py        граф деталей, разбивка на SP/E-SP, нумерация по ходу трубы
  reference.py     справочник «База» и таблица DN ↔ дюймы
  excel_writer.py  выгрузка в формате «Евгений (2)» + лист расхождений
  cli.py           командная строка
```

## Что пока не автоматизировано

Дополнительная резка спулов под транспорт. В `WELDING LIST` таких швов нет —
они наносятся на чертёж вручную (`S22`, `S30`–`S49` и подобные). Чтобы
программа их ставила сама, нужен критерий резки: предельная длина спула,
вес или габарит. Пока такие листы честно помечаются в «Расхождениях».

## Форматы изометрий

Разбирается формат Intergraph/nanoCAD (текст в аннотациях). В подшивке
встречается второй формат — российский, СИБУР (обычные встроенные шрифты,
таблицы `FABRICATION MATERIALS` / `ERECTION MATERIALS`, ведомости швов нет).
Такие листы сейчас пропускаются с отметкой в «Расхождениях».
